# Seminar leftover briefs

Repo-only. No Notion. One markdown file per talk.

The object is **not** “AI directions on their data.” It is the leftover
scientific question their design already almost answers (or cannot), plus
one decision. A learner is licensed only after leftover is structured.

## Commands

| When | Command |
|---|---|
| Before the talk (40×/year) | `/seminar` — dump slides, notes, URL, DOI |
| After you sat it (3 min) | `/seminar-after` |
| Rare: collab before talk, or independent run after after-log | `/seminar-deep` |

Skills: `.cursor/skills/seminar/`, `seminar-after/`, `seminar-deep/`.

## Layout

`seminars/YYYY-MM-DD-speaker.md` — pocket on top; after-log appended to
**this file**. Four YAML keys: `date`, `leftover`, `decision`, `asked`.

Do not add `INDEX.md` or `LEDGER.md`. Skip rate is grep on `decision:`.

Do not commit speaker PDFs. Briefs only.

## Dual-use

No directions or recipes for pathogen enhancement, reverse genetics,
synthesis/genome design, or toxin/select-agent sequence design.
Uncertain → refuse the direction; questions must not transfer capability.

## Routing (short)

Thin listing or noise → `SKIP`. Cannot tell what they measured → `ASK`
two control questions, no project. Structured leftover → then a
question-change. Writeups are not Dos.
